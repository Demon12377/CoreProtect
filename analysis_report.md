# Полный анализ плагина CoreProtect

Этот отчет представляет собой детальный анализ плагина CoreProtect. Его цель — оценить эффективность методов защиты, выявить потенциальные уязвимости, которые могут быть использованы гриферами, и дать рекомендации по настройке для обеспечения максимальной безопасности на сервере.

## 1. Методы защиты и отката: Реактивная оборона

CoreProtect — это, в первую очередь, инструмент **реактивной защиты**. Он не предотвращает гриф, а позволяет быстро и эффективно устранять его последствия. Основа этой системы — три команды:

### Команда `/co inspect` (или `/co i`)
Это — главный инструмент для расследования. При активации инспектора вы можете узнать историю любого блока:
- **Левый клик по блоку:** Показывает, кто его поставил.
- **Правый клик по блоку:** Показывает, кто его сломал.
- **Правый клик по сундуку/двери:** Показывает, кто с ними взаимодействовал.

Эта команда позволяет точно определить ник грифера и время, когда был нанесен ущерб, что является ключевой информацией для отката.

### Команда `/co rollback` (или `/co rb`)
Это — основное оружие против грифа. Команда позволяет откатить действия конкретного игрока по заданным параметрам:
- `u:<user>` — ник игрока, чьи действия нужно отменить.
- `t:<time>` — временной промежуток (например, `t:2h` — последние 2 часа).
- `r:<radius>` — радиус действия отката от вашего местоположения.
- `a:<action>` — конкретное действие (например, `a:-block` — только сломанные блоки).

**Пример:** Команда `/co rollback Griefer t:1h r:50` отменит все действия игрока `Griefer` за последний час в радиусе 50 блоков. Плагин восстановит сломанные блоки, удалит поставленные и вернет украденные из сундуков вещи. Это мощнейший инструмент, который полностью нивелирует ущерб.

### Команда `/co restore` (или `/co rs`)
Эта команда — ваша страховка от ошибок. Если вы неправильно выполнили откат (например, указали не того игрока или неверное время), `/co restore` с теми же параметрами **отменит сам откат**, вернув всё в то состояние, в котором оно было до вашего вмешательства.

**Вывод:** CoreProtect предоставляет полный набор инструментов для борьбы с последствиями грифа. При правильном использовании администратор может отменить практически любой ущерб, нанесенный игроками.

## 2. Уязвимости и «слепые зоны»: где CoreProtect бессилен

Эффективность CoreProtect напрямую зависит от его конфигурации. Если плагин не настроен на отслеживание определённых событий, он их «не видит» и, следовательно, не может откатить. Это создаёт «слепые зоны», которыми могут воспользоваться гриферы.

### Уязвимость №1: Лавакасты и водяной гриф

Один из самых разрушительных и труднооткатываемых видов грифа — это заливание построек лавой или водой. Если жидкость уничтожает сундуки, факелы, рельсы и другие неполные блоки, это может нанести колоссальный ущерб.

- **Источник уязвимости:** Отключенные опции в `config.yml`.
  - `water-flow: false`
  - `lava-flow: false`
  - `liquid-tracking: false`

- **Как это работает:** Если эти параметры установлены в `false`, CoreProtect не будет отслеживать разрушения, вызванные потоками жидкости. Плагин зафиксирует, что грифер поставил блок-источник лавы, но не сможет связать с ним все последующие разрушения. Откат уберёт только сам источник, а все сожжённые сундуки и уничтоженные предметы останутся.

### Уязвимость №2: Отключенное логирование взрывов, огня и поршней

Гриферы часто используют ТНТ, огонь и поршни для нанесения урона.

- **Источник уязвимости:** Отключенные опции в `config.yml`.
  - `explosions: false` — не логируются взрывы ТНТ, криперов.
  - `block-burn: false` — не логируются сгоревшие блоки.
  - `pistons: false` — не отслеживаются блоки, сдвинутые поршнями.
  - `entity-change: false` — не логируются блоки, изменённые сущностями (например, Эндерменом).

- **Как это работает:** Любая из этих опций, установленная в `false`, создаёт брешь в защите. Например, если отключено логирование взрывов, откат действий грифера, который взорвал чей-то дом, не восстановит разрушения.

### Уязвимость №3: Неосторожное использование `blacklist.txt`

Файл `blacklist.txt` позволяет полностью исключить из логирования определённых игроков, сущностей или события. Это мощный, но опасный инструмент.

- **Источник уязвимости:** Добавление в `blacklist.txt` критически важных для логирования вещей.

- **Пример катастрофы:**
  Если администратор добавит в `blacklist.txt` следующие строки:
  ```
  #tnt
  #creeper
  #fire
  ```
  Это **полностью отключит** логирование взрывов ТНТ, криперов и распространения огня. В этом случае CoreProtect будет абсолютно бессилен против поджигателей и подрывников. Откатить такой гриф будет невозможно.

**Вывод:** Безопасность сервера напрямую зависит от того, насколько полно и корректно настроен `config.yml`. Любое исключение из логирования должно быть хорошо обдумано, так как оно потенциально создаёт уязвимость.

## 3. Чего не хватает для идеальной защиты: Проактивный подход

Важно понимать, что CoreProtect — это инструмент **реактивной защиты**. Он не *предотвращает* гриф, а лишь *устраняет его последствия*. Даже с идеально настроенным конфигом, грифер всё равно может нанести ущерб. Администратору придётся потратить время на расследование и откат, а игроки могут испытать стресс, увидев свой дом разрушенным.

Для полноценной защиты необходим **проактивный подход**, который изначально запрещает игрокам совершать деструктивные действия на чужой территории.

### Роль плагинов на приват территорий
Эту задачу выполняют плагины для привата территорий, такие как **WorldGuard**, **GriefPrevention** или **Residence**. Они позволяют игрокам «заприватить» свою землю, после чего другие игроки (не добавленные в приват) не смогут:
- Ломать и ставить блоки.
- Открывать сундуки и двери.
- Использовать механизмы.
- Разливать лаву и воду.

### Идеальная связка: CoreProtect + WorldGuard
Лучшая стратегия защиты сервера — это комбинирование двух типов плагинов:
1.  **WorldGuard (проактивная защита):** Предотвращает 99% попыток грифа, защищая частную собственность.
2.  **CoreProtect (реактивная защита):** Служит «страховкой» на случай, если гриф всё же произошёл (например, на незаприваченной территории или если владелец привата сам добавил грифера в участники).

**Вывод:** CoreProtect — незаменимый инструмент для любого сервера, но он не является панацеей. Для построения комплексной и надёжной системы защиты его необходимо использовать в связке с плагинами на приват территорий.

## 4. Рекомендуемая конфигурация для максимальной защиты

Ниже представлен пример конфигурации `config.yml`, в котором включены все опции, необходимые для максимально полного логирования событий. Эта конфигурация поможет минимизировать «слепые зоны» и даст вам возможность откатить практически любой вид грифа.

**Важно:** Не используйте `blacklist.txt`, если в этом нет крайней необходимости. Любое исключение из логирования — это потенциальная уязвимость.

```yml
# CoreProtect Config | Рекомендуемые настройки для максимальной защиты

# Базовые настройки
use-mysql: false         # Установите true, если используете MySQL
table-prefix: co_
check-updates: true
api-enabled: true

# Настройки логирования (включить всё для максимального охвата)
verbose: true
rollback-items: true
rollback-entities: true
skip-generic-data: true  # Можно оставить true для экономии места, отключает логирование горения зомби и т.п.

# Логирование блоков
block-place: true
block-break: true
natural-break: true
block-movement: true
pistons: true
block-burn: true
block-ignite: true
explosions: true
entity-change: true
sign-text: true
buckets: true
leaf-decay: true
tree-growth: true
mushroom-growth: true
vine-growth: true
sculk-spread: true
portals: true

# Логирование жидкостей (критически важно!)
water-flow: true
lava-flow: true
liquid-tracking: true

# Логирование инвентаря и предметов
item-transactions: true
item-drops: true
item-pickups: true
hopper-transactions: true

# Логирование действий игроков
player-interactions: true # Не откатывается, но полезно для расследований
player-messages: true
player-commands: true
player-sessions: true
username-changes: true

# Интеграции
worldedit: true

# Прочие настройки
default-radius: 10
max-radius: 100
```

### Итоговое заключение
CoreProtect является стандартом де-факто для защиты серверов Minecraft от грифа. Его сила заключается в гибкости и мощи системы откатов. Однако его эффективность полностью зависит от правильной и полной конфигурации. Отключение даже одной, на первый взгляд незначительной, опции логирования может создать уязвимость, которой воспользуются опытные гриферы.

Для обеспечения всесторонней безопасности рекомендуется:
1.  **Использовать** конфигурацию с максимальным логированием.
2.  **Не использовать** `blacklist.txt` без крайней необходимости.
3.  **Комбинировать** CoreProtect с плагином на приват территорий (например, WorldGuard).

При соблюдении этих правил ваш сервер будет надёжно защищён от большинства видов грифа.
